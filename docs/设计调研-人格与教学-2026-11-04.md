# 小鲸的人格与教学：调研与方向建议

2026-11-04。本文是讨论稿，不是已批准的实施方案。本轮只做公开资料调研；没有修改插件实现、操作 DSH、调用真实 DeepSeek 或访问正式记忆。

## 1. 先记住我们在解决什么

Mianiii 要的小鲸：有自己的喜好、反应和主见，能打闹、嬉戏、开玩笑；相处自然。讲题时能从题意带着他看出关系、画图、建模，讲到他明白；无需一口气给出大段术语和完整讲义。普通聊天与教学应延续同一个角色和关系。

本轮结论：保留人格与生活连续性，收拢对话指挥权；用少量具体对话校准讲法。不要把“更像人”继续翻译成更多后台模块，也不要把“简化”翻译成删掉所有记忆、生活或约束。

当前插件的 prompt 竞争是待验证的根因假设。上一轮源码审查找到竞争要求和实际错误，但本轮没有做同一 DeepSeek 下的模型对照，不能宣布“减掉多少 prompt 就恢复多少能力”。

## 2. 原插件真正值得学的部分

### 人格是倾向，表达不必每轮执行固定动作

已直接读取原插件 `main` 快照 `527bd907eeb54cb055763cc05432e30158a51a26`。角色档案把性格、典型反应和口吻示例当作可供自然使用的设定，不要求每轮逐项表演；口吻示例也不是真实经历。[角色档案源码](https://github.com/menglimi/astrbot_plugin_private_companion/blob/527bd907eeb54cb055763cc05432e30158a51a26/companion_v2/role_profile/context.py)

表达模块提供 free / guided / constraint 路径，默认样式常量为 free；free 函数分支不追加该块风格指令。它的较详细引导也允许长短变化、按任务提供足够内容，避免固定反问、刻意碎句和强行制造亲近。这个文件在之前参考的 `f1e4c17` 与本次快照内容一致。这里只确认模块与分支行为，没有推断每位用户实际启用了哪种模式。[表达源码](https://github.com/menglimi/astrbot_plugin_private_companion/blob/527bd907eeb54cb055763cc05432e30158a51a26/companion_v2/conversation/humanized_expression.py)

对小鲸的设计推论：把“每句先情绪、必须短、必须停下来问”等要求改为情境倾向。人格要有具体偏好、动机、在不同情况下的反应；不能靠每句加称呼或语气词代替。

### 同一个角色，背景与本轮请求分清

普通回复桥把生活、记忆和关系作为有来源的背景，保留宿主的会话历史与主回复链；跨场景时角色及已有承诺不重置。人设共创文档要求逐步确认动机、口吻和背景，少量试演后再调整，不从一句模糊描述擅自编完角色。[回复背景源码](https://github.com/menglimi/astrbot_plugin_private_companion/blob/527bd907eeb54cb055763cc05432e30158a51a26/astrbot_host/core_reply_context.py)、[人设共创方法](https://github.com/menglimi/astrbot_plugin_private_companion/blob/527bd907eeb54cb055763cc05432e30158a51a26/companion_v2/persona_designer/methodology.md)

对小鲸的设计推论：教学无需第二份人格。她认真讲题时可以减少玩笑，但保留同一段关系、语气习惯和对学生的了解。角色状态可给回应底色，当前明确求助优先；不要由多个状态模块分别下“现在只能说什么”的命令。

### 生活连续性有价值，但功能清单不是效果证明

原插件的生活候选、主动联系、后台预算和记忆分层确有各自职责；其文档把角色状态、用户事实、共同经历和表达风格分开。当前 v7 已有内置长期记忆，不能继续沿用旧搜索摘要中“只有外部记忆”的介绍。[私聊与记忆指南](https://vue.syuan.org/guide/private-memory/)、[当前源码 README](https://github.com/menglimi/astrbot_plugin_private_companion/blob/527bd907eeb54cb055763cc05432e30158a51a26/README.md)

这不要求小鲸迁移它整套记忆实现。继续使用 Hindsight 可以符合项目目标；先解决已有记录的主体、来源与召回错误。生活功能按能否改善相处来保留，不按与原插件的覆盖率验收。

## 3. 技术资料支持什么，不支持什么

| 一手资料 | 可以支持的判断 | 边界 |
|---|---|---|
| [Anthropic：Effective context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) | 明确原则、少量典型例子、按需取材料；过细的行为分支难维护，过于空泛也无用 | 工程经验；“最小必要信息”不等于强制短 prompt，也不证明小鲸当前故障原因 |
| [FollowBench，ACL 2024](https://aclanthology.org/2024.acl-long.257/) | 多层约束跟随是一项会失败的能力，值得测每条规则与它们的组合 | 13 个当时模型与特定任务；不能外推出当前 DeepSeek 的退化幅度 |
| [Generative Agents，UIST 2023](https://arxiv.org/abs/2304.03442) | 记忆、观察、计划和反思的组合可改善模拟角色行为的可信度 | 25 角色沙盒；不能证明长期中文陪伴质量，也不能推出必须复制整套生活系统 |
| [Persistent Personas，EACL 2026](https://arxiv.org/html/2512.12775v2) | 长对话及目标任务中的角色保持值得单独验收 | 合成对话、所测模型与评估条件有限；不是小鲸/DeepSeek 的实测 |

上述跨来源支持的方向是：人格连续性与任务表现需要共同评估；让每轮可见的信息与指令有清楚职责。它们不支持“规则一律有害”“让她自由说就一定讲得对”或“加反思就会像人”。

对“降智”的具体调查应检查最终组装结果：本轮有哪些规则、分别来自哪里、适用于什么情境，是否与当前请求竞争。不能只看某个人设文件，也不能只数 token。

### DSH 与 DeepSeek：先用已有边界

DSH 上游已有统一提示组装职责：有序的静态 section 与动态 context 分开。这能作为整理插件边界的参考。这里读取的是上游 `master`，实施时必须核对本机已安装版本，不能直接照搬新接口。[DSH 官方源码文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/system-prompt/README.md)

DeepSeek 官方说明缓存依赖可复用的请求前缀，且不保证每次命中。稳定人格与变化材料分开有成本上的依据；缓存命中与“更聪明”是不同指标，不应混为一谈。[DeepSeek 缓存文档](https://api-docs.deepseek.com/guides/kv_cache/)

## 4. 教学：让建模过程看得见，帮助随回应变化

认知学徒的原作者文章讨论如何展示专家的解题策略，再逐渐让学生承担决策。对小鲸最有用的是可核对的教学推导：为什么挑这个例子、为什么画箭头、哪条关系允许排除一种情况。这里说的示范不要求暴露模型内部思维链，也不是一篇证明 ICPC 提分的实验。[Collins、Brown、Holum：Cognitive Apprenticeship](https://www.aft.org/ae/winter1991/collins_brown_holum)

例子学习的研究综合表明，例子应帮助学生把具体步骤与原理连起来；强迫自解释、比较或附加任务，在复杂材料下也可能增加负担，学生需要时应提供解释。由此可推到小鲸：卡在建图时直接示范；学生已开始推时给他空间。不能强制每隔两句发问，也不能永远只问不讲。[Renkl：Example-Based Learning](https://onlinelibrary.wiley.com/doi/full/10.1111/cogs.12086)

“先具体、再抽象、需要时命名”适合作为你的默认教学偏好。它不该成为所有问题必须依次通过的程序。你直接问定义、完整证明或复杂度时，仍然正常回答。

用座位题校准时，期待她先把“想去哪里”画成关系，再用小例子讨论交换与冲突，逐步抽出有用结构。完整题面尚未提供，当前不能把“只会出现环和链”或相应最优策略当成已证结论；一条出边也不排除多条入边。口语化应保留数学正确性。

## 5. 下一版的取舍建议

这是结合资料、上一轮审查和你的偏好得出的设计推论，尚未用真实 DeepSeek 对照验证。

| 方案 | 能解决什么 | 主要代价 | 建议 |
|---|---|---|---|
| 继续逐项移植原插件 | 扩充生活和互动能力 | 当前冲突与记忆归属未解决，验收范围继续扩大 | 暂缓 |
| 大幅清空状态和约束，只留人设 | 快速减少干扰 | 可能失去连续性，也会丢必要的事实与授权边界 | 不采用整体清空 |
| 收拢人格与上下文，保留有用能力 | 直接针对割裂、规则竞争、维护困难 | 需要追踪每轮实际材料，并用连续对话验证 | 推荐 |

推荐方案先守住五件事：

1. 人格有一个明确来源：身份、动机、偏好、关系、少量反应样例；由你逐步确认，不擅自增加亲属或恋爱标签。
2. 动态材料说明发生了什么、何时发生、属于谁；减少额外的表演命令。保留角色生活感，避免学生事实变成她的经历。
3. 讲题默认贴住当前卡点；图、小例子、简短解释和提问按需要选择。短回复不等于讲懂，长解释也不天然专业。
4. 事实核验、授权、预算、执行回执继续由程序守住；语气、安慰、讲法与训练取舍留给模型判断。
5. 先复用 DSH 与 Hindsight；只有已证实的能力缺口才新增插件机制。后台能力能独立停用，故障不要拖垮普通对话。

先用这五种场景共同验收，而不是拆开给“闲聊人格”和“教学人格”打分：

| 场景 | 看什么 |
|---|---|
| 闲聊聊到她自己的兴趣 | 有具体反应与偏好，能开玩笑，不连续播报状态 |
| 闲聊中转入一道题 | 同一个人自然认真起来，不重启成教材腔 |
| 学生卡在题意到建模 | 能拿一个小例子或图解释那一步，必要时直接示范 |
| 学生纠正她的推理 | 修正具体结论，保留关系与语气，不用撒娇掩盖错误 |
| 插入打趣后继续讲题 | 接得住，也能回到原来的卡点，不丢上下文 |

## 6. 建议的下一步

先共同打磨一段“闲聊 → 讲题 → 被纠正 → 接着讲”的连续对话样板，确定你喜欢的反应、节奏和讲法。样板只是说明味道，不能成为逐字台词库。

随后再做离线提示来源清单，把冲突、重复和错误适用范围逐项整理；与记忆主体、来源核验缺陷一起设计最小改动。真正跑 DeepSeek 对照前，另行确认次数与预算，使用隔离会话及记忆，保持同一模型；本次调研不包含这笔调用授权。

结论把握：原插件机制与上游文档事实为高；教学和上下文的一般原则为中高；具体修改能否让小鲸达到你要的感觉仍待验收。没有足够证据给出效果百分比或断言某一个 prompt 就是全部根因。
