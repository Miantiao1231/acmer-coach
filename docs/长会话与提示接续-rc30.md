# rc.30：长会话与提示接续

本地预览，未发布。接续 rc.29 已修的审查问题，本轮继续核对完整工具说明/返回、原生请求与压缩输入，没有调用真实模型或改写正式对话。

## 新确认与修复

| 问题 | 处理 |
|---|---|
| 已验证节点即使明确要求复习，在没有长期课程时仍被拒绝 | 允许有理由的 `purpose=review`，不抹掉已有验证；前置、理由、时长、课程版本检查继续生效。 |
| setup 文案仍指示第一次聊天先体检、先问 CF 号 | 仅在正式配置或训练确需核对时体检，已有信息不重复问。 |
| 泛指昨天发生什么被导向训练日志 | `coach_journal` 限定训练事实，普通日常经历按需用 Hindsight。 |
| diagnose 参数仍要求确定失败因果 | why、summary、node 的说明与观察/待确认一致，不把引用存在等同于因果或能力结论。 |
| coach_note 默认节点说明落后于实际行为 | 明确当前课优先；显式节点仍优先，无当前课时保留既有回退。 |
| 处境与撤卷返回仍强迫确认/追问/排程 | 当前已解释就不重复问；撤卷后不自动拉去排程。未新增坏卷数据分型，旧检测结果语义保持兼容。 |
| 当前背景作为普通插件消息逐轮进入历史 | 在完整支持的 DSH 上改用原生命名当前快照，相同内容不再重复发送；回退宿主保持旧消息机制。 |
| DeepSeek in-history 更新后旧系统头可能被原生压缩继续使用 | 静态配置首次接续或注册变化时核对现行投影，必要时请求 DSH 开启规范化序列，压缩输入随之使用当前系统头。 |

## 复用宿主的范围

新增 `lib/request-context.js`，由现有状态钩子和记忆桥共同使用，没有新建记忆库、摘要引擎或历史清洗器。

- 同时检测公开 `systemPrompt.context`、`refreshContext`；只有注册能力但没有请求前刷新能力的旧宿主，仍走原消息回退，避免拿到上轮缓存。
- 钩子先完成原有状态计算和召回，再发布会话独立的快照。DSH 请求前刷新读取本轮内容。
- 主动唤醒清除当前训练背景，无本轮召回时清空当前记忆快照；不同会话不共享内容。
- 规范化前使用公开 `assemble`/`renderPrompt` 和 `deriveEventMessage` 获取权威当前值，不直接读未投影的旧文本。
- 只有所有现行非空系统消息都来自原生 `system-prompt` 时才自动规范化。其他插件拥有系统消息时跳过，不替它作决定。

规范化使用 DSH 现有 `startsRequestSeries`，由宿主维护模型可见投影；插件不删除或重写原始用户/助手消息和原始系统事件。检查仅在会话首次接续或静态注册变动后进行，不每轮重复装配系统提示。

## 隔离验证

实际 NEXT 公共运行时、DeepSeek 的 `in-history` 与 `addition-only` 能力组合，连续三轮合成对话：

| 观测 | 修复前 | 修复后 |
|---|---|---|
| 人格变更后有效系统节点 | 旧头与新版并存 | 单一当前系统头 |
| 普通插件 coach_state 消息 | 1→2→3 | 使用命名原生快照 |
| 第三轮相同状态 | 再发一份 | 不再追加相同快照 |
| 原始旧系统事件 | 保留 | 仍保留 |

再通过公开 `BasicCompactionEngine.compactRegion` 与实际 token meter 捕获摘要调用。摘要服务被本地占位生成器替代，fetch 全部拒绝：

```json
{
  "currentInSummary": true,
  "oldInSummary": false,
  "headCurrent": true,
  "rawOldBefore": true,
  "rawOldAfter": true
}
```

这是请求结构验证，不证明真实摘要模型一定正确概括每个偏好，也不证明实际聊天人格已经达标。

## 保留的边界

- 原生快照内容改变时仍会追加历史，本轮没有实现“所有历史背景永远不累计”。原生框架提供的是当前快照替代早期快照的明确语义与相同内容去重。
- 旧的插件背景消息与既有摘要没有自动清洗；本轮修的是当前上下文的身份以及已复现的旧系统头压缩路径。
- 原生压缩仍使用宿主的通用模板，没有替换整个压缩引擎，也没有新增付费判别模型。
- 外来系统消息、未提供相应公开能力的宿主按边界跳过或回退，不能保证所有第三方插件组合都已覆盖。
- 未操作正式 DSH 界面、未发正式聊天、未调用真实 DeepSeek 或 Hindsight 提炼；需要重启 DSH 加载新模块。
