# 「我会永远陪着你」vs dsh-coach 满血对照

- 原仓库：`github.com/menglimi/astrbot_plugin_private_companion`
- 版本：`7.0.13`，commit `f1e4c17`（2026-11-02 克隆）
- 对照范围：`companion_v2/**/*.py`（685 个文件，156,063 行）
- 我们的范围：`dsh-coach` 工作树，`index.js + lib/*.js`（19,503 行）
- 方法：四路只读代码对照（状态/日志/成长、主动/平台、记忆/表达、对话/关系/基础设施），逐文件清单见 [`原插件文件清单-2026-11-02.md`](./原插件文件清单-2026-11-02.md)

## 0. 一句话结论

不是「还差 5 个补丁」。原插件是一个 **685 文件、15.6 万行的陪伴 OS**：生活、记忆、表达、主动联系、群聊、多模态、管理台、七项内置能力都在同一套 SQLite 与宿主总线上。dsh-coach 是 **1.95 万行的教练插件**，上一轮 1–5 补的是「生活状态机骨架」。

所以「满血」要分两层看：

- **陪伴核心**（她像一个活着的人）：还差 5 个 P0 行为，能补，工作量以「周」计。
- **产品层**（陪伴小屋/七项能力/QQ 多窗口）：不是补代码，是换产品形态；dsh web 里大部分不适用，需要单独决定要不要做。

## 2. P0：直接影响「她像活着」的五块

### P0-1 日记、梦、阅读没有真实内容

原插件：

- `role_work/journal/writing.py`：模型写日记/梦，带人格指令、材料、近期日记、风格；180 秒预算、2048 tokens；输出严格限制 `body/form/recall/afterglow`。
- `journal/material_producer.py`、`reading_materials.py`：从活动、会话、文本产物、阅读回执生成带 `kind/origin/date/source` 的材料；阅读只取回执里的文本区间。
- `journal/selection.py`：材料超 64 条或 48KB 时，模型只选原始 `material_ids`，不能摘要改写。
- `journal/triggers.py`、`scheduling.py`：每日 23:50 注册；睡眠完成触发梦；先 operation 占位，按角色/类型/日期去重，失败显式 retry。
- `journal/service.py`、`codec.py`：按日期+kind 的版本化档案，支持删除/恢复、派生 `summary/dream_fragments/continuity`。
- 阅读：`role_work/life/runtime.py` 的 `start_reading` 读实际文本，校验 `content_hash`，`role_reader.consume` 产出读后感。

我们现在：

- `lib/companion-state.js` 的 `advanceJournal()` 是模板字符串：今天补觉/看书/发呆，一天一段。
- `lib/activity-runtime.js` 的 `dreamText()` 是模板：梦见在看某本书。
- `lib/activity-ledger.js` 的 reading 只有标题 + 25 分钟计时器，没有文本、没有读后感、没有来源。

差距：她的「日记、梦、读过的书」目前是壳。补这一块的收益最大，也最容易看出「不是满血」。

### P0-2 状态维护只有 energy，预算和上下文都不够

原插件：

- `role_work/state/maintenance.py`：后台模型维护 11 个状态字段；默认 30 分钟；180 秒任务预算、150 秒模型超时、1024 tokens；输入含近期对话、模拟历史、日程、技能、睡眠回执、四轴心情；失败留预检结果。
- `maintenance_context.py`：3 天对话游标，最多 32 条/10000 字；按 1/2/3 天取旧模拟，明确「旧模拟不是新证据」。
- `humanized.py`：表达强度 0–100，三档 facet/字数预算（220/420/700）；每天 04:00 本地巡逻，无模型，记录并裁剪 30 天。
- `cycle.py` + `cycle_state.py` + `cycle_prompts.py`：持久虚构周期，六阶段、锚点、natural/unknown/first_day、阶段表达；日期由系统维护，模型只给 applicability。
- `mood/models.py`：四轴 1–10 由模型写；半衰期回落 + 单步 allowed 区间校验；joy 回基线、负面回 1；有概率门、中性带、跨窗口说明。

我们现在：

- `lib/state-maintenance.js`：6 秒超时、600 tokens；只给最近 500 字用户文本；只维护 energy + 9 个自由文本字段；每 30 分钟一次，但只在用户回合触发；失败直接丢。
- `lib/body-state.js`：四轴由确定性衰减 + 正则加减，模型不能写数值；没有 allowed 区间、概率门、中性带。
- `lib/companion-state.js` 的 `roleStateLines()`：每轮无条件拼一行，没有强度/预算/巡逻。

差距：状态是「程序模拟」，不是「模型维护的主观状态」；跨天、周期、心情都没有连续性。

### P0-3 长期记忆与反思只有第一层

原插件：

- 分层：事实 atom、经历、习惯、人物卡、反思、群记忆、置顶。事实写入必须有原始 human message 证据（`writer._validate_proposal` 的 `memory_attribution_unproven`）；经历/习惯/人物卡不能反过来当事实证据。
- `reflection.py`：持久批次状态机 `selecting → prepared → running → received → modelled → complete/empty/failed/partial`；输出 `summary + proposals + pending_decisions + anniversaries`，逐项校验。
- `reflection_recovery.py`、`checkpoints.py`：原始模型输出先落盘；失败可 repair 子批次，只重送 rejected 项；启动恢复未完成批次。
- `episodes.py`：周期私聊摘要，游标 `covered_through`，双方消息、消息数/分钟触发。
- `habits.py`：入站自动计数，时段桶 + 原话签名 + 不同日期 + 30 天时效，不调模型。
- `recall_*.py`、`semantic.py`、`mmr.py`：向量 + 关键词混合召回、MMR、可重建索引、逐条回源。

我们现在：

- `lib/claims.js`：JSONL claim + 投影，evidence 只有 quote/time/messageId，没有 source revision/span，不能感知撤回。
- `lib/memory-select.js`：分词重叠选择，没有索引/分页/候选上限/逐条源复核。
- `lib/reflection-runner.js`：批次只在内存，失败整批 5 分钟后重试，已成功项和原始输出都丢。
- 没有周期 episode 摘要、没有习惯自动计数、没有向量/混合召回。

差距：记忆是「一层平铺的 claim」，不是「证据分层的长期记忆」。

### P0-4 后台时钟、每日巡逻、成长回执

原插件：

- `host/background.py` + `host/application.py`：单一 wake loop、后台槽位、`next_wake/deadline`、投递 reconcile、跨窗口 attention lease。
- `journal/scheduling.py`：每日 23:50 注册，宿主 wake loop 驱动，只补当天不补积压。
- `humanized.py`：每天 04:00 状态巡逻。
- `growth/progress.py`：从已完成生活/日记回执生成 progress_note，pending 人工接受后应用。
- `execution/*`：持久任务准入、lane/并发、fencing、重试/取消。

我们现在：

- 睡眠/活动/日记都在 `index.js` 的 `agent/pre-step` 里懒结算；没有对话就停住。
- `proactive-worker.js` 有 60 秒 tick，但只做主动消息，不结算睡眠/阅读/日记/状态巡逻。
- 重启会丢待发/待反思任务（内存状态）。

差距：状态机对，但时间轴是被动的；夜里没人说话，她不会「到点睡、到点醒、到点写日记」。

### P0-5 主动联系只有主干，没有事件族和 followup

原插件（`proactive/*` 45 文件）：

- `scheduling.py`(1719 行)：14 类事件按优先级轮询；idle/interval/5 分钟 slot/小时曲线/share/burst/closing；followup/open-loop；busy/sleep hold；平台熔断；诊断窗。
- `service.py`(1848 行)：一次机会 → draft → 呈现守卫 → 去重 → pending 判官 → 投递；支持多段、语音、戳一戳、图片。
- 事件族：早安/午间/晚间、失眠、饭点、天气/预警、新闻、健康、日历/约定、成长、日记/梦、回忆、屏幕回看、余额、关系事件。
- `wake_detection.py` + `morning_rhythm.py` + `wake_events.py`：typed evidence fusion 判断用户醒来，学习作息，角色 morning + 最多一次 nudge。
- `budget.py`：本地日决策/投递额度、pending/unknown 预留、真实 token/cost。
- `persona_judge.py`：草稿后判官，阈值 62、缓存 180 分钟、失败/未知 = withhold。

我们现在（`lib/proactive-*.js`，约 812 行 worker）：

- 每 tick 选 1 个现成候选 → draft → judge 同一 tick → followup 发送。
- 有 intensity/interval/idle/burst、judge 阈值 62/缓存 180m、未回复计数、日额度、正文去重、`message.id` 回执。
- 没有：事件账本、事件优先级、followup/open-loop、busy/sleep hold、醒来/晨间链、真实 token/cost、投递队列/重试/reconcile、多段/语音/戳一戳/图片。

差距：主干像，事件密度和「接着说」的手感差得远。

## 3. P1：对话、关系、基础设施

1. **忙碌回复门**：`conversation/busy_gate.py` 在角色日历忙碌时延迟被动回复 60–300 秒，紧急/命令绕过，忙完有恢复缓冲。我们只有睡眠 rest gate；上课/课时/押卷只抑制主动联系。
2. **私聊防抖与收尾沉默**：`private_debounce.py` 自适应 1.5–4 秒合并窗口；`private_closing.py` 识别晚安/道别/感谢/简短应声，避免互道晚安死循环。我们只有 dsh 自带 coalesce + 0.5–1 秒 presenceDelay，没有收尾守卫。
3. **跨窗口连续性/递话**：原插件在群转私聊时注入同人 30 分钟内群话题 + 角色回复摘要，严格只读对方本人；私聊/群白名单转述有持久任务和回执。我们单窗口，没有 awareness。
4. **关系记忆采用流程**：原插件模型只能 propose，reviewed/adopted 必须有人类 actor，提示词只注入 adopted；我们 `pending.accept`、`style.accept`、`relation.add` 可被模型直接调用。
5. **工具副作用幂等**：原插件 operation_id + 参数哈希 + replayed；我们只有文件锁和 claims key 去重，重试/并发可能重复写承诺、习惯、里程碑。
6. **持久任务监督**：原插件 SQLite 任务准入、lane/并发、fencing、重试/取消证明；我们进程内 timer + 内存缓冲，重启丢任务。
7. **屏幕同意与原件**：原插件每次截屏有 request/coverage/clock quality/不可变原件/按窗口 consent；我们只有 80 字摘要 + 一个开关。
8. **配置分层**：原插件 installation/role/window 三层，稀疏 patch、revision/edit token、迁移；我们配置分散在 env/页面/状态文件，没有统一校验和原子 patch。
9. **对话内容能力**：群聊、引用、合并转发、图片/语音/视频/文档、TTS、分段、表情包、生图——大部分是 QQ/宿主形态，dsh web 需要另接通道。

## 4. P2：产品与平台层

这些不是「漏写的函数」，是产品形态差异：

- **QQ/AstrBot 平台**：在线/离开/忙碌/隐身、自定义状态、输入中、戳一戳、语音、图片、群管理、Qzone。dsh web 没有等价 API；要做只能接 QQ 桥。
- **陪伴小屋**：18 个工作区、3D 体素小屋、四套主题、16 通道感知仪表盘、token/缓存/TTFT/回执观测。我们没有管理台，只有简单 person 页面。
- **七项内置能力**：Content（创作）、Image（生图/改图）、Screen（识屏）、Reality（摄像头/手机/米家/华为健康）、Together（共处房间）、Game（五子棋等）、Live（B 站直播）。
- **多账号/多窗口/群聊**：三层配置继承、私聊/群聊隔离、跨窗口身份连续、群参与规则（Laya 阈值、空气护栏、黑话、相识卡）。
- **存储/迁移/备份**：独立 SQLite、schema 版本/迁移、快照备份、跨盘迁移、operation/inbox/outbox。
- **外部记忆桥**：第三方 memory provider 注册、P6 只读契约、MemoryCompanion 协同。

## 5. 不建议照搬的部分

- QQ Qzone、群管理、群记忆、多账号 ACL：dsh 当前单用户，补了也用不上；等 dsh 有群/多用户再说。
- 3D 体素小屋、四主题、16 通道仪表盘：产品 UI，不是陪伴能力；要做也是另开前端项目。
- Reality/米家/华为健康/Live/Game/Together/Image：需要外部设备或平台账号，和教练主线弱相关。
- 原插件的授权分级/operation 回执：单用户下收益低；但**工具幂等**和**持久任务**这两条对可靠性有实际价值，值得保留优先级。

## 6. 建议路线（只算实现+测试，调效果另算）

### M1「她真的在生活」：3–4 天

1. 日记/梦接模型写：材料生产者（活动/对话/阅读回执）+ 选材 + 严格输出 + revision/派生。
2. 阅读接真实文本：来源 + content_hash + 读后感 + 阅读回执。
3. 状态维护升级：3 天对话/模拟历史、预算/超时/tokens、四轴心情模型契约、每日 04:00 巡逻。
4. 把睡眠/日记/状态巡逻挂到 `proactive-worker` 的 60 秒 tick（先不新建宿主）。

### M2「她记得住」：2–3 天

1. 反思批次持久化 + 原始输出检查点 + 部分成功 repair。
2. 证据从 quote 升级到 source span + 撤回联动。
3. 周期 episode 摘要 + 习惯自动计数/跨日资格。
4. 表达规则治理：样本审核、退役/恢复、注入轮换、送达后反馈。

### M3「她会主动」：2–3 天

1. 事件账本 + `(id,revision)` 去重 + followup/open-loop。
2. 睡眠/忙碌 hold + 早晨/失眠/饭点节奏。
3. 投递队列/重试/reconcile（至少把 `message.id` 回执做成持久账）。
4. 预算：真实 token/成本 + pending 预留。

### M4「对话与关系」：3–5 天

1. busy gate + 收尾沉默 + 自适应防抖。
2. 关系记忆「提案→审阅→采用」状态机。
3. 工具 operation_id + 参数哈希幂等。
4. 屏幕 consent/原件（如果还要识屏）。

### M5「产品层」：按需，不建议一次做

管理台、七项能力、QQ 桥、多窗口/群聊，每一项都是独立项目。
