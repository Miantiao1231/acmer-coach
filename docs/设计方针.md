# 设计方针

> 这份文档回答「**这个教练为什么这么设计**」，不回答「先做哪个功能」。
> 想看怎么用，去 README；想看代码长什么样，去读源码。

---

## 一、一句话命题

> **教练的价值不是知识，是位置。**
>
> 它站在局外、手里有地图、且不投入自尊。
> 在局里的人看不见河的全貌 —— 这跟聪明程度无关，是位置问题。

由此推论：**初学者没法自己给自己当老师。**
排优先级需要「什么重要、什么先什么后、哪里是坑」——
而这些恰好是初学者没有的知识。**这是循环依赖，必须由外部打破。**

市面上不缺讲解算法的资料，也不缺题。缺的是**替你排顺序**的那个人。

## 二、为什么「AI 助手」式的教练会失败（五条诊断）

在动手之前，先把这一类系统的常见死法列清楚。以下五条来自一个已退役的
旧实现（SQL 分析 + LLM 转述那套），每一条都有具体证据。

| # | 诊断 | 表现 |
|---|---|---|
| 1 | **分工反了** —— 程序在做判断，LLM 在做转述 | 用 SQL 判弱点、用规则选平台，LLM 只把 JSON 翻译成人话。这就是它「像个网站」的根因 |
| 2 | **单位错了** —— 系统数「题」，教练该管「知识点」 | 输出是「DP 44%」「搜索 20%」。但「DP」不是知识点，是一本书 —— 那是学科分类，不是考纲 |
| 3 | **掌握度靠推断，不靠检测** | 有一道题提交 11 次（9 次 TLE）才 AC。历史数据能说「花了很久」，**说不出「卡在哪」** |
| 4 | **闭环是虚构的** | 弱点日志全项目只写不读；夜间任务又把标签整体重写回来 —— 闭环活不过一天 |
| 5 | **自我报告 ≠ 现实** | 定时任务报「上次运行成功」，而消息一条没送到。同一个病：统计说 AC 88 次，另一个口径按 82 算 |

**共同点**：每一条都是「系统以为自己在工作，实际没有」。

这五条决定了下面所有设计 —— 尤其是「判断归谁」和「什么东西可以信」。

## 三、设计原则（八条）

### 原则 1：输出是「位置」，不是「池子」

> 网站给你一个池子（可无限）。教练给你一个位置（必须唯一）。

- 每日指令**只能给一个动作**，禁止候选列表、禁止「你可以考虑」
- 每条指令必须含：**做什么 + 时间盒 + 交付物**
- 检验：看到回答后能**直接开始做**，不需要再思考

这条是整套设计的分水岭。一旦给出候选列表让人自己挑，这个系统就退回成一个网站了
—— 那它就**没有存在的理由**。

### 原则 2：判断归 LLM，记录归程序

| 谁 | 干什么 |
|---|---|
| **程序** | 记录事实（做了没、提交几次、耗时、题库检索、抓题面） |
| **LLM** | 读代码判因、出检测卷、决定推进还是复习、排优先级 |

**把判断从程序手里拿回来。**

具体的落地：工具**报事实、给出口，但不下结论**。「该不该复习」不由 SQL 打分决定，
而是把相关事实摆到教练眼前（哪些节点放得最久、做过几题、独立几次），让它判断。
工具只拦**机械上做不到**的事（前置没满足、块和块叠在一起）。

> 推论：**别指望工具把教练的活全干了。** 能机械检查的只是一部分，
> 剩下的写不进代码。（这条后来被证实了 —— 见原则 5 的边界。）

### 原则 3：掌握靠检测，不靠推断

| 项 | 做法 |
|---|---|
| 标准 | **预先设定**（不是事后按表现调） |
| 单元 | 单元化，每单元一次形成性检测 |
| 不达标 | **不是「重学」，是换一种教法** → 重测平行卷 |
| 达标 | 才推进；不达标不推进 |
| 参照系 | **自己的目标**，不是别人 |

**关键：「对了几题」不该是主指标** —— 题目难度是出卷人控制的，可以操纵。
扛得住的指标是：**① 独立（无题解无求助）② 限时 ③ 能讲清**。

所以进度有**四级**，而且「自评」和「检测」**必须分开**：

```
不写      = 未学
studying  = 在学       开了头、还没达标。跨天是常态
learned   = 学过       自评学过，没做检测
verified  = 已验证     过了章节检测，有证据
```

把 learned 和 verified 合成一个「会/不会」，就等于退回原则 2 要治的那个病。
`verified` 因此**手标不了** —— 它不是靠自觉，是枚举里就没有这个选项。

### 原则 4：单一真相源，视图必须生成

- 地图只有**一份**（YAML），进度只有**一份**
- **任何副本都是 bug**（吃过亏：两份标签映射文件导致排序漂移）
- **视图（网站 / 图）必须由脚本从真相生成，不许手写**

推论：工具里同一个查询**不许写两遍**。规范版只有一个，其余都是调用方。
这条在测试里有专门的关卡盯着 —— 同一个 SQL 在源码里出现两次就是两份真相。

### 原则 5：不靠自觉，靠结构强制

> 写在文档里的规则是**建议**，写在代码里的规则是**法律**。

「今天说了明天又忘」不是记忆问题，是**强制力问题**。治法见第五节。

**但这条有边界，得说清楚**：结构只能强制**机械可判**的那一半。
「新知识点必须先讲」可以做成闸门（没带 `teachMinutes` 就拒绝），
因为「讲没讲过」是可判的；而「这块该不该复习」判不了，只能靠教练的判断。
**别把后者也硬做成规则** —— 那会变成一个用错误数据下命令的系统。

### 原则 6：命名是终点，不是入口（讲题规范）

| 段 | 内容 | 要求 |
|---|---|---|
| 1 **推导** | 从题目条件出发，一步步推到做法，**含走过的死路** | 不跳步；不用未解释的术语 |
| 2 **命名** | 推完再给这个结构/技术命名 | **禁用「这题是 X 算法」开头** |
| 3 **扩展** | 变体、邻居结构、边界 | 孤立点记不住，连成网的才记得住 |

**语言标准**：`越简单的语言 + 越完备的逻辑就越好`。
两者同时成立，不是二选一 —— 简单但跳步 = 听不懂；完备但晦涩 = 看不懂。
检验：**一个没学过这算法的人，能否复现这条推理链。**

**交互禁忌**：禁止苏格拉底式连环提问。提问要**稀疏**，只在最关键那一步问一个。

**节奏归他，不归你**：一段 = 一个自然步骤，讲完停一下留插话的口子。
三段式是**结构**，不是「一条消息发完」。

### 原则 7：优先级 = 依赖（硬）× 权重（软）× 缺口（变）

| 维度 | 性质 | 用法 |
|---|---|---|
| **依赖关系** | **不变**（不会线段树就学不了树套树，是逻辑） | **先开这个，且单独开一遍** |
| 赛场权重 | 会变，且数据源互相打架 | 第二遍叠加 |
| 个人缺口 | 会变 | 第三遍标位置 |

**分三遍画，一遍一个维度。** 第一遍绝不掺权重 ——
一旦开始想「这个重要不重要」，就会把它排到前面，而依赖会被画错。

节点上的两条轴就是这么来的：

- `tier`（重不重要）—— 来自人工标注，软的
- `entry`（学不学得起）—— 来自题池 p25，硬的

**两者缺一不可**：地图只会说「**允许**学什么」，不会说「**合适**学什么」。
后者要看他的当前水平 —— 那是教练的判断。

### 原则 8：地图要串成网，不是列成表

每个结构必须标：**邻居 / 变体 / 边界**。

看到过一个结构之后，**价值不是省掉推导，是扩充库存** ——
下次见到同族的能认出来。

## 四、架构

### 4.1 数据层（单一真相源）

```
MAP.yaml        地图：节点 + 依赖边 + 两条轴（tier / entry）
DEPENDS.yaml    前置关系的**唯一真相源**（人维护，MAP 由它生成）
PROGRESS.yaml   进度：游标 + 四级状态 + 检测记录 + 判因台账 + 押着的动作
SCHEDULE.yaml   日程：忙事 + 排的块 + 实际用时
```

**为什么时间要单独一份**：课表会随时改 —— 考试周、临时有事、假期。
**时间是变量，不是静态输入。** 这决定了「今天做什么」其实是**排程**，不是选点：

| 情况 | 计划怎么做 |
|---|---|
| 容量缩小（考试周） | **只做复习，不推进** —— 保「不退步」，砍「新内容」 |
| 容量扩大（假期） | 加速推进，但**不线性加量**（会疲） |
| 临时打断 | 那几天重排，不是简单堆到后面 |

**硬规则：容量变化时重算优先级，但游标只前进不倒退。**

### 4.1.1 块结构：一个块 = 一道题的完整循环

```
├─ 40min  自己做（限时，到点必须停）   ← 止损点就在这里
├─ 10min  解决遗留
├─ 10min  重写
└──────── 入复习队列
```

**这解决了三个问题**：

1. **止损点有了** —— 40 分钟到点必须停。治「卡题恋战」靠的是表上写着下一段，
   不是意志力
2. **复习队列有了自动入口** —— 做完就入队，不靠记得
3. **「听讲」和「重写」被排进时间表** —— 否则它们永远是"有空再做"，实际等于不做

**那 20 分钟分两种情形**：

| 情况 | 干什么 |
|---|---|
| 限时内**独立做出来** | 复盘思路 + 一句话总结（**不重写**） |
| **没做出来 / 看了题解** | 教练讲 + 重写 |

**附带数据价值**：块结构天然产出「独立做出 vs 听了讲才会」这个信号 ——
这是掌握度最直接的证据，也是 `coach_log` 里那个 `independent` 字段的来历。

### 4.1.2 排程规则

```
块长 = 题目循环 60min ／ 复习一题 25min ／ 章节检测 90min（3 题）
填法 = 按地图依赖顺序，从游标往后填
止损 = 块的时长是硬边界
记录 = 计划时长 vs 实际时长 → 几周后能知道真实做题速度
```

**⚠️ 没有「容量 = 空闲 × 0.75」这条了。** 早期版本有这个硬校验，
后来**撤掉了**：排多排少是教学判断，工具只该拦物理上不可能的
（压着忙事、块叠块、出网格）。排太满的后果让「计划 vs 实际」事后说话 ——
那比一个写死的系数更诚实。

### 4.2 逻辑层

| 部件 | 输入 | 输出 |
|---|---|---|
| 每日指令 | MAP + PROGRESS | **一个动作**（含时间盒、交付物） |
| 章节检测 | 当前节点 | 抽题 + 限时 + 判因 + 过/不过 |
| 判因 | 代码 + 提交记录 | 「不会 / 不熟 / 不认真」三分类 |
| 复习决策 | 各节点掌握时间 | 复习 or 推进，带理由 |

**判因的三段式**：① 错在哪 → ② 为什么会这么错 → ③ **下次怎么判断**。
第三段是重点 —— 只写到 ①② 等于告诉他"你错了"，他还是不知道下次怎么办。

而且每条判因**必须引用代码原文**，工具当场校验那段原文真在代码里。
抄不出来会被拒绝。这和「指令必须带节点 id」是同一个把戏：
**让含糊的话物理上说不出口。**

### 4.3 形态：一个插件，三合一

```
插件
├── host 端    工具（能调）+ 钩子（强制）
├── web 端     进度面板（读同一份数据渲染）
└── 数据       YAML，唯一真相源
```

**一个插件给三样**：工具 + 强制 + 界面。

**为什么插件比「让模型去读文件」硬**：后者靠模型自觉，前者由 harness 执行。
这正是原则 5 的落地。

**界面是视图，不存数据**（原则 4）。

## 五、强制力：怎么让规则真的生效

**四层，一层比一层硬。**

### 第一层：单一真相源（防漂移）

地图一份、进度一份。**删掉所有旧副本。**
同一件事有两个出处，早晚会打架 —— 而且打架时**没有任何报错**。

### 第二层：规则少到能背，且每次会话必加载

规则放**每次都会加载的地方**，不放数据文档里（那是数据）。
每条都能机械检查，写成「违反就是没做好本职工作」的形式。

### 第三层：结构上让绕不过去

**让正确的行为成为唯一能走通的路。**

规则说「指令必须带节点 id」，而节点 id **只能从地图取到** ——
那它为了产出指令，就**必须先去读地图**。这不是自觉，是结构约束。

同理：`coach_assign` **一次只收一个节点**，所以它物理上给不出候选列表。
`coach_diagnose` 要求引用代码原文，所以「边界没处理好」这种话说不出口。

### 第四层：把规则放进 system prompt

规则进 **system prompt，不是消息流**：行为约束每轮都得在场，
而消息流会被长对话把尾巴挤掉。

⚠️ **但文本必须静态**：这一段每轮都参与组装，现算内容会打穿 prompt cache
（DeepSeek 的 cache 是前缀命中，system prompt 每轮变动会让后续 token 全部 miss）。
所以只在插件加载时读一次 —— 改了规则文件要重启。

## 六、明确不做

| 不做 | 原因 |
|---|---|
| ❌ 弱点百分比驱动的每日推荐 | 会误导。不同口径下同一个知识点能给出 44% 和 82% |
| ❌ 从历史数据自动推断掌握度 | **已证伪**：一道题提交 11 次，数据说不出卡在哪 |
| ❌ 图当主要视图（Mermaid 那类） | 试过，效果差。**技能树是有向图，得专门画** |
| ❌ 推送作为唯一交付通道 | 死过一次：定时任务报成功，实际零接收 |
| ❌ 刷题数量当进度单位 | 单位错了，教练管知识点不管题数 |
| ❌ 计算几何 | 多个数据源一致：低频。投入产出比最差 |
| ❌ 再写一套「更聪明的」分析引擎 | 问题不在不够聪明，在分工反了 |
| ❌ 大而全的重构 | 大部分代码是**工具**（抓题面 / 检索 / 题库），那些有用 |

## 七、遗留问题

这些是**已知的、还没解决好的**，写出来免得后来者以为是漏掉了：

| # | 问题 | 现状 |
|---|---|---|
| 1 | **前置边是人工整理的** | 349 节点 / 401 边铺完了，但**没有逐条复核过**。出现「为什么 X 依赖 Y」的疑问是正常的，欢迎提 issue |
| 2 | **地图的粒度** | 现在到「区间 DP」这一层。「运用方式」还算不算独立知识点 —— 没想清楚 |
| 3 | **冷启动精度** | 数据只用来缩小范围，位置靠检测。第一次的起点可能偏，要几次检测才收敛 |
| 4 | **判因的主观性** | 「不熟」和「不认真」的边界靠教练判断，不同模型可能给出不同分类 |
| 5 | **块时长的普适性** | 40 分钟那个止损点是针对一个人调的，别人可能需要不同的数 |
