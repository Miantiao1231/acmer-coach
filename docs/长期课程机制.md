# 长期课程机制

课程既要跨会话继续执行，也要回答“为什么安排这个阶段、为什么先学它”。
模型负责解读目标与真实表现；插件检查记录引用、节点前置和阶段验收，不生成统一的
几个月算法清单，也不把一段听起来合理的规划理由当成已经存在的学习证据。

`CURRICULUM.yaml` 保存目标、阶段、本周主线、进入阶段时的事件快照和修订历史。
`PROGRESS.yaml` 保存学习、检测、判因和做题事实，`SCHEDULE.yaml` 保存近期时间块
及实际完成。课程引用事实，不复制另一份掌握状态，也不内置个人 rating、目标或课表。

## 工具流程

1. `coach_curriculum read` 查看路线、当前阶段、待完成单元和 `needsReview` 警告。
2. `coach_curriculum assess` 查看真实证据目录；先核实用户目标、起点与时间预算。
3. 依据足够时建立 training 阶段；不够时建立 diagnostic，远期假设用 provisional。
4. `create` 建立路线，随后每天沿用当前阶段，`coach_assign` 带版本及阶段关联理由。
5. 用原有工具记录做题、判因与检测。新观察形成后修订后续路线；验收通过再 `advance`。
6. 本周主线到期或目标、时间、表现改变时复盘，用 `revise` 保存依据与旧版本。

写操作均需 `expectedRevision` 和至少 10 字的 `reason`；首次 create 的版本为 0。
旧上下文不能覆盖新路线，当前有效路线不能用 create 悄悄替换。完成整条训练路线后可
建立新路线并保留审计历史。文件损坏会报错，不会当成没有课程直接覆盖。

## 证据目录与引用

`assess` 只读取账本，不改变记录。每条结果有：

| 字段 | 含义 |
|---|---|
| `id` | 事件位置及完整内容指纹组成的引用，写入阶段的 evidenceRefs |
| `eventId` | 同次观察的事件身份，验收时区分“改记录”与“做了新训练” |
| `source` | check、diagnosis、practice 或 schedule |
| `node/date` | 记录属于哪个地图节点、哪一天 |
| `signal` | gap（暴露缺口）或 baseline（已观察到的能力起点） |
| `summary/fingerprint` | 记录摘要与内容指纹 |

来源与信号的规则：

| 账本事实 | 信号 |
|---|---|
| 检测 failed / overTime | gap |
| 检测 passed | baseline |
| 有有效代码引用、wrong/missing 类型和解释的判因 | gap |
| 实训 solved=true 且 independent=true | baseline |
| 实训没做出，或依赖提示/题解做出 | gap |

取消的卷子、rating、节点状态、没有代码证据的判因不会被列为短板。非法记录跳过，
缺少日期等必要字段的条目不能引用。日程 actual 与进度 passes 中同一次实训去重，
优先保留 practice；只有日程里有的真实完成记录仍可引用为 schedule。

对象字段换序不会改变引用。记录内容改变会使旧 id 失效，写课程时需重新 assess；
同条 check/diagnosis 的成绩、结论或备注变化不会产生新 eventId。追加检测是新事件。
实训按日期、节点和题号识别事件，同次做题从 schedule 迁入 practice 仍是同一事件，
不能拿修改备注或迁移来源凑出“又完成了一次”。没有题号的同日同节点条目也按原工具
的覆盖语义视为同次事件。

assess 最多返回最后 200 条，并给出 `evidenceCount/evidenceTruncated`。截断时用
`evidenceNodes` 缩小到相关节点，不能凭空填一个未返回、未核实的引用。

## 阶段如何编排

基础字段 `id/title/outcome/nodes/competencies/exitCriteria` 分别标识阶段、能力成果、地图节点、比赛能力和验收方法；一个阶段至少绑定一个真实地图节点或比赛能力，地图节点最多 50 个，整条路线 1–30 个阶段。读题、决策、团队沟通这类没有单一算法节点的阶段直接填 `competencies`。

VP 题目里的 `competencies` 和复盘里的 `competencies` 会生成稳定证据 id（如 `vp:event:problem:competency`），进入课程时被快照；能力阶段只能用进入阶段后的新 baseline 记录通过 `advance`。

还必须提供：

| 字段 | 要回答的问题 |
|---|---|
| `kind` | 这是诊断、训练，还是远期尚待确认的设想？ |
| `finding` | 正在补 gap、基于 baseline 做 extension，还是 unknown？ |
| `basis` | 观察到了什么，或什么尚待确认？至少 10 字 |
| `goalContribution` | 解决它怎样服务长期能力目标？至少 10 字 |
| `priorityReason` | 为什么把它排在这个位置？至少 10 字 |
| `estimatedHours` | 预计投入多少小时？诊断/训练为正数，待定可以为 0 |
| `evidenceRefs` | 用哪些 assess 返回的真实 id 支撑阶段？ |
| `uncertainty` | 尚未确认什么？诊断/待定至少 10 字，训练可空 |
| `diagnosticMethod` | 怎么取得新观察？诊断至少 10 字，其他阶段可空 |

三种可编排阶段：

* **training**：每个节点或比赛能力都必须有对应证据。`finding=gap` 必须引用该节点/能力的 gap；
  `finding=extension` 必须引用该节点的 baseline。无关节点的失败不能用来凑依据。
  所有节点都必须列入 `requiredVerified`，不能用空数组逃过检测。
* **diagnostic**：`finding=unknown`，明确待确认问题、取证方法与能力目标的关系。
  可以还没有引用，也可以引用已有观察；不能把猜测写成已确认的短板。
  requiredVerified 为空，因为验收要看本阶段的新观察，而不是旧的掌握标签。
* **provisional**：`finding=unknown`，保留远期设想和不确定性。不能作为当前阶段，
  下一阶段仍待定时也不能 advance 进入；先改成有依据的训练或明确的诊断。

前置顺序来自地图依赖。程序只认可显式 learned/verified，以及在之前安排的必验训练
节点；诊断或待定不会自动提供“已掌握”的承诺。同一训练阶段的节点也按前置顺序列出。
不能通过 cursor 的祖先闭包假设前置已经掌握。实际布置训练时还会重新检查前置是否有
显式记录，未来会学到的内容不能替代今天的记录。

优先级文本和预计投入仍需模型作教学判断。程序能拦住缺证据、错误前置和绕过验收，
不能证明目标贡献、估算或路线排序在教育上最优；字符门槛也不证明解释正确。
读取路线还会返回 `remainingEstimatedHours/estimatedWeeks/budgetWarnings`：按剩余阶段
估时、每周预算和目标日期粗估容量，超出预算、周预算未知或待定阶段尚未估时都给提示。
这只用于提醒调整范围，不把周平均当成精确日程，不作为拒绝执行的门槛。

## 执行、验收与调整

`focusNodes` 只允许来自当前阶段；为空时沿用该阶段全部节点。`focusUntil` 可留空，
有日期且已到期时先复盘。`weeklyHours=0` 表示尚未确认，不伪造每周可用时间。
有效课程的普通动作只能沿当前主线，`coach_assign` 带当前 `curriculumRevision`，
`why` 解释该动作怎样服务阶段成果。

补漏用 `purpose=remediation`，复习用 `purpose=review`，并给至少 10 字的
`routeReason`，说明与当前阶段的关系和返回条件。复习需要该节点有 learned/verified
记录。任务在原 pendingActions 中附课程版本、阶段、目的与理由；旧任务也保留。
当前单元未结束时先继续或明确撤销，再开另一节。临时算法问答不会自动改路线。

进入阶段时保存 `enteredAt/entryEvidenceRefs/entryEvidenceEvents`。advance 必须同时满足：

* diagnostic：每个节点都有进入时未出现、日期不早于进入日的新有效观察。
* training：地图节点全部 verified，且每个节点有本阶段新的独立做出或检测 passed 事件；能力目标全部有本阶段新的 baseline 证据。
* 当前阶段没有待完成动作，也没有检测卷等待判定。

旧记录改内容或换来源不能替代新事件。诊断阶段不能通过 revise 改成训练或删除待诊断
节点绕过新观察要求；最后只有诊断阶段的路线也不能直接宣布完成，需按新结果追加后续
路线再推进。模型还需判断阶段能力成果是否达到并说明依据，不按题数、周末或单题 AC
自动推进。原检测工具关于独立性与延迟复测的判断逻辑仍保留，verified 本身不证明
检测条件足够，模型仍需核对。

修订不能重写已完成阶段，不能跳过或重排当前阶段。实质改变当前阶段的节点、成果、
验收条件或证据依据时会重新记录进入快照，之前的事件不能当作新阶段的成果。
每轮会话状态提供目标、主线、编排依据、未完成任务、缺少新观察的节点及复盘警告。

## 旧路线与边界

旧 v1 CURRICULUM 可读，显示 `needsReview`，但不能照原有无依据阶段继续布置或推进。
插件不会在读取时自动重写文件、补造依据或修改训练事实。先 assess，再 revise 为当前
及后续阶段补齐上述字段与证据，明确保存为 v2；已完成阶段保留为历史 legacy。

本功能没有新增 VP 自动读取、后台周报或课表页面。VP 复盘目前仍需通过已支持的
记录入口形成本人真实训练记录，不会自行连接服务器或推定比赛短板。

## 开发验收

`node --test dev/curriculum-check.mjs` 使用临时数据，覆盖路线持久化、证据编排、前置、
迁移、新事件验收、修订冲突、主线到期、任务关联和真实工具/会话状态集成。
`node --test dev/curriculum-evidence-check.mjs` 覆盖目录边界、引用与事件身份、来源迁移、
镜像去重、非法记录过滤和输入不变。

`dev.sh` 同步课程、证据和编排模块以及规则、文档与测试；两个课程套件的失败都计入
退出码，并对真账本做前后指纹检查。`verify.mjs` 第 0 关比较源码与已安装副本的运行时
模块内容，包括证据和编排模块；副本落后就终止。`dev/run-all.sh` 在隔离安装副本中跑
全套验收。没有建立课程的环境保持原有工具行为。
