# 小鲸的维护与记忆职责

按 2026-11-06 正式版 `2.12.0` 工作区核对。这里说明现在谁在做什么；历史审查、原插件对照和旧版本日志保留当时状态，不能当作当前调用链。

## 先认清五种数据

| 数据 | 谁负责 | 它能证明什么 |
|---|---|---|
| 学生过去的偏好、经历与约定 | `lib/hindsight.js` 连接自己的 Hindsight bank | 主要跨会话召回线索；提炼可能过时，不能认证掌握 |
| 训练目标、课程、进度、日程、VP 记录 | `strategy.js`、`curriculum*.js`、`teaching.js` 与 `index.js` 的训练工具 | 已记录的训练事实与教学决定；计划不等于完成，AC 不自动等于独立 |
| 小鲸角色档案、少量边界、承诺与共同经历 | `person.js` + `claims.js` | 本地接续资料；分清角色与学生，核对来源和时间，不能因存本地就压过 Hindsight |
| 候选、表达偏好、反思游标与任务回执 | `reflection*.js`、`episodes.js`、`task-queue.js` | 整理过程走到哪；待审不等于采用，运行成功不等于消息已说出 |
| 睡眠、阅读、日记与其他角色生活状态 | `companion-state.js`、`life-tick.js` 及生活模块 | 角色的模拟状态或有材料的产物；不是学生作息、健康或训练能力 |

训练日志由 `training-log.js` 从训练账本生成，页面与 `coach_journal` 看同一份结果。它辅助还原某天，不另存一份训练真相，也不同于小鲸自己的 `journal-archive.json`。

`rc.29` 的 Hindsight 待写内容在 `DSH_HOME/data/acmer-coach/tasks.json`，复用 `task-queue.js` 的锁、租约和重试，按 endpoint/bank 隔离。内容先经现有脱敏再落盘，每条自动尝试最多 3 次；入库 HTTP 接受后标 accepted，不声称已完成提炼。`coach_status` 分别报召回和保存状态；`coach_task` 的 `queue=memory` 可查、取消或明确重试，不返回正文。关闭记忆桥后不发请求，换库不把旧内容投到新库。

工具操作使用可选 `operation_id` 时，以现有 SQLite 事务模式串行核对结果缓存。执行异常或回执无法缓存时保留待核对标记，不自动重写；用户应先查询实际状态。缓存保留期和容量有限，不承诺任意崩溃窗口的全局恰好一次。

`rc.31` 将学生临时处境统一交给 `person.js` 的只读时效投影：默认到原消息所在本机自然日结束，旧的自动七天期限不再让当天的处境跨天生效。记录保留在原账本；状态读取、每轮注入和人格页面共用有效期限，缺失或无效时间不能当成当前事实。确有跨天依据时，工具可用明确期限；同一句原话更正来源、时间或期限也会记录变化。页面将过期项标为历史，并区分今天反思计数与上次反思摘要。

`coach_student_context set` 使用核对到的原消息时间，不能用工具执行时间给旧原话续成今天；无法核对时间时拒绝写入。反思批次恢复时，摘要与原 `rawSavedAt` 成对更新，旧批次不覆盖已有更新摘要，不把恢复时间当生成时间，也不重置当天调用计数。

`rc.30` 的 `lib/request-context.js` 只是两处现有入口的宿主适配：`registerStateHook` 发布 `coach:state`，`applyHindsight` 发布 `coach:memory`。每会话 WeakMap 存本轮快照，不是跨会话记忆；请求前由 DSH `refreshContext` 读取。宿主同时具备 context/refreshContext 才启用，否则保留原消息路径。静态提示首次接续或注册变动时，通过公开装配比对与 `startsRequestSeries` 规范化原生系统头；外来非空 system 消息不接管。原始事件不删除，快照变化时历史仍可累计，详见 [长会话与提示接续](长会话与提示接续-rc30.md)。

## 同一事实只有一个写入入口

`person-events.jsonl` 是本地角色与关系资料的事实事件账本，`person.json` 保存投影及待审、说法、presence、反思计数等工作流。不要分别编辑两份文件来“修复记忆”；通过 `companion` 或人格页面写入，由 `savePerson → claims` 处理变化与并发。

事实先认主体：学生说“我喜欢黑咖啡”属于学生；明确给小鲸设定喜好才属于角色；两人一起复盘属于共同经历；教练怀疑“这里可能没懂”仍是判断。反思的 profile/library 候选必须有 `subject: role`，旧无主体候选保留供查看，但不能直接采用。主体标记也需结合原话看，不能把模型标记本身当语义证明。

模型修改学生边界、承诺、置顶、互动习惯以及已有关系/经历时，`index.js` 把 `teaching.source` 注入 `createCompanionTool` 核对当前会话原话。真人页面通过宿主已鉴权入口写入，表示本人整理。核对只证明引文存在，不证明解释正确；旧资料缺消息 ID 或时间时保持未知。`coach_note` 同样区分已核对原话和教练判断，不会把笔记变成掌握证书。

旧事件中的 `source: user` 只是已有写入标签，不能单凭它断言是本人点页面写的；有些投影回写也使用这个标签。追溯时同时看实际入口、引文和可取得的会话出处。

`rc.26` 的 `companion role.remember` 可记录角色已发表的自身偏好或相处习惯，经当前会话助手正文核对后，事件保留 `source: role-self`、`subject: role` 及消息出处。它不改身份背景或学生边界；模型使用 `profile.set` 需要核对用户给角色设定的原话，真人页面保留原编辑能力。

`rc.27` 进一步禁止模型直接通过 `profile.set` 修改 `background`：核对到学生原话不等于它属于角色来历。来历由用户页面明确编辑，反思候选仍须用户确认；普通改名和自身偏好留档能力保持。

每轮仅带身份、短性格、必要约定和教学接续；生活附录改为 `companion read` 按 `section` 查询。完整行为与本轮验证见 [背景与人格接续](背景与人格接续.md)。

`rc.28` 让进行中的课也能带上本节题目线索和对应节点的续课笔记；当前课优先于训练游标，显式指定节点仍优先。笔记保存教练观察、学生回应的出处和可调整的接法；收课可选 `nextStep` 复用已有字段，不新增课堂记忆库。旧观察不覆盖当前回应，也不自动触发讲课。

角色身份、边界或关系冲突与当前明确更正不一致时，按当前意愿接续，只在相关且仍不确定时确认。不要每轮重复问关系，也不要要求当前对话先服从旧称呼。

## 从哪里找入口

```text
index.js apply
  ├─ 静态 persona/rules → DSH systemPrompt.section
  ├─ applyCompanion → 原生 inbox 合并连续纯文本
  ├─ applyHindsight → 首步召回、完成轮次异步归档
  ├─ registerStateHook → coach_state 当前背景与本地接续线索
  └─ proactive worker → 本地生活 tick；已授权时生成并投递主动消息
```

| 当前运行链 | 主要模块与调用者 |
|---|---|
| 训练与页面 | `index.js` 注册工具、`/coach/api/*` 和状态钩子；`lib/client.js` 是浏览器入口；`strategy/curriculum/teaching/training-log` 分别管目标、路线、续课、读侧时间线 |
| 对话接续 | `companion.js` 合并输入；`person.js → memory-select.js` 选少量本地线索；`hindsight.js` 独立召回；`last-seen.js` 统一最近用户时间；`persona-audit.js` 当前只记日志 |
| 可选反思 | `index.js → reflection-runner.js → reflection.js/reflection-batch.js/episodes.js`，产生待审候选与表达候选，不自动把候选变成角色事实 |
| 本地生活与可选模型产物 | `proactive-worker.js → life-tick.js`；睡眠由 `sleep-runtime/ledger/settings` 结算，阅读由 `activity-runtime/ledger + reading` 管，`journal` 管日记/梦，`state-maintenance/patrol` 管维护，`workload/interaction-log/habits/growth` 提供有限背景 |
| 主动联系 | `proactive-state/rhythm/sources/events` 管节奏与占用；`proactive-compose → warmth` 辅助生成审核；`proactive-send` 通过 DSH followup 投递，`proactive-lock` 防两个进程重复运行；外部话题与屏幕分别由 `external-sources`、`screen-observer/consent/originals` 管 |

即使训练账本已存在但内容为空，首步仍会带角色与约定背景。只有首次缺训练账本且学生明确要开始训练时才提示体检；闲聊不因空进度进入建档流程。

共享存储在 `json-store.js`；训练账本的冲突检查在 `ledger.js`；工具的可选操作去重在 `tool-operations.js`；后台任务的租约、终态与重试在 `task-queue.js`。修同一种写入问题时先找这些共用入口，不再为新模块复制一套锁。

## 七个开关，费用分别计算

| 开关 | 当前效果与默认值 |
|---|---|
| Hindsight | 默认不启用；有效配置文件或 `COACH_HINDSIGHT=1` 开启，`0` 显式关闭。启用后的远端归档/提炼可能产生服务端模型费用 |
| 后台生活与反思 | 页面 `backgroundLlm` 默认关；`COACH_BACKGROUND_LLM=0/1` 覆盖页面值。控制生活 tick 的日记、梦、读后感、状态模型维护，以及记忆/表达反思；关掉后本地状态结算照常进行 |
| 生活即兴 | 页面 `lifeImprov` 独立默认关；每日默认2次，可设1—6次，至少间隔4小时，失败与已预留调用计预算。只向模型提供角色资料，生成带有效期的模拟近况；不受主动联系或后台生活开关代管 |
| 自主阅读 | 默认关，页面独立授权；每天最多 2 轮、每轮最多 4 次模型请求、每天合计最多 8 次，失败也计入。每次正文最多约 6000 字；正文读取凭据核对通过后才保存进度和笔记，截断片段不冒充整本读完。分享进入主动联系队列，不能绕过联系节奏 |
| 主动联系 | 默认关，明确授权后 `coach_proactive arm`，关闭用 `disarm`。启用后 draft/judge、必要的重写以及唤醒后的正式回复会调用模型；不受后台生活开关代管 |
| 外部话题 | `settings.external` 默认允许，`COACH_EXTERNAL_SOURCES=0` 强制关；控制已开启主动联系时的天气/新闻资料。关闭它不等于关闭屏幕或主动联系 |
| 屏幕观察 | 在已开启的主动联系链路中，观察开关与页面限时授权必须同时满足，worker 还检查活跃时长、冷却和每日次数。视觉模型调用独立计费；普通观察只持久保存摘要及出处，旧版本原件不会升级时批量删除，可在页面查看并删除已有原件 |

后台生活开关不控制普通聊天模型、Hindsight 后端、主动联系、生活即兴或自主阅读的模型调用。每个开关有明确的费用范围，不是全插件的总预算。停掉主动联系，也不会替你清空已经允许的其他开关。生活即兴和自主阅读预算保存在 `proactive-state.json` 的独立日计数中；任务历史淘汰不恢复额度，任务队列仍负责租约与去重。

旧 `arbiter` 配置及 `COACH_MEMORY_ARBITER` 仍为兼容保留，当前正常接话和 Hindsight 召回链没有调用记忆仲裁模型。旧设置可保存，但状态中的 `effective.arbiter` 固定为 `false`，旧设置写入回执也会说明当前不启用，不能把存储值当运行状态。

以上结论交叉核对了 codegraph、生产 imports/调用点、直接单测、`dev.sh` 同步名单和 `package.json` 的导出。公开导出目前是主插件、client 和 package.json；这不保证没人通过磁盘路径引用内部模块。图谱没找到调用者或一次 rg 无匹配，都不足以支持删文件。本轮没有清理历史数据，也没有删除模块；以后真要退役，再同时处理直接引用、测试、同步与兼容数据策略。

## 修改后怎么验

1. 先在源码目录查 codegraph 状态和相关调用者，确认改的是唯一写入实现；保持已有未提交工作。
2. 使用隔离的 `DSH_HOME/COACH_DATA_DIR/COACH_DB` 跑相关离线测试；Windows 沙箱的系统 Temp 若报 rename EPERM，把 TEMP/TMP 指向仓库内专用临时目录。不要拿正式记忆库验证。
3. 静态人设或规则改动需要重启 DSH。三份安装副本与源码是不同验收对象，源码测试绿灯不能证明安装副本已更新。
4. 同步索引，并记录实际跑过的检查。人格自然、教学是否讲懂仍由用户自己的真实对话验收；不要自动替用户付费聊天。

不做的事：不因维护文档新增另一份状态文件；不让反思或日记重写训练账本；不为每种口吻再加一个评分器和门禁。当前仍有多个生活状态文件，它们的用途和调用边界已列明，本轮没有宣称完成大规模架构拆分。
