# 比赛依据与教学模式

训练路线先回答“目标比赛里要完成什么任务、本人被什么障碍挡住”，再选知识点。Rating 可以帮助找题池，不能证明某项能力已掌握，也不能单独决定下一阶段。

## 三种信息分别负责什么

| 资料 | 用途 | 不能据此声称什么 |
| --- | --- | --- |
| `COMPETENCIES.yaml` | 九项通用比赛能力；关联精确 MAP 节点 | 它们不是官方考纲，教学验收阈值不是比赛规则 |
| `coach_lesson` | 记录短回合讲课中的学生回应与续课位置；误记可更正上一条 | 记录了回应不等于掌握；独立做出还要具体题目与结果 |
| `CONTEST_PROFILES.yaml` | 有限真题样本支持的诊断任务与取舍提示 | 不代表专题频率、奖牌线或未来题目预测 |

预写教案卡已经移除：具体边界以可靠资料和真实题面核对；小鲸先用人话讲核心，再根据学生回应选择下一步。`coach_schedule` 可以保存每周固定上课时段，时段外以练习或原定休息为主，学生明确要求即时讲课时照办。

`coverage` 沿用原加载器，自动汇总配置内的样本数量、题解核验数量和年份。西安配置保留 `xian-pending` ID，并填入2025十三题；同题也出现在通用配置中，两个配置不能相加当成独立题数。模型映射是教学解释，不是唯一解法、知识点频率或学生掌握证据。NWERC仍是独立扩展参考。

另保留[56场中国区资料索引](china-contest-sources.md)：45场区域赛、7场EC-Final、4场邀请赛。链接只是候选，按需核对，不随每轮对话注入；省赛、网络赛、同题镜像不混入区域赛样本。原始工作表未修改，索引内杭州2024错配由Stage8 Cangqian省赛改为Stage25 Hangzhou、场次1893。

四个 profile 均保留 `provisional`：表示只能在说明限制后用于诊断，不能输出“完整官方考纲”。`solutionReviewed` 表示读过题解并对照题意，未运行全部解法或交互器，也未完整核验现场奖牌榜单。未来即使使用 `reviewed` 状态，也不能去掉这些边界。

### 原始资料的版本差异

上海和香港的题面镜像可能写UCup或训练营重赛年，原赛年由官方赛事别名与命题组题解核定。香港PDF页脚跳号，样本使用实体PDF页序。香港K的题解概述写字典序最大，正式题面要求最小；[正式题面](https://contest.ucup.ac/download.php?contest_id=3169&id=15442&type=statement)优先。上海H/I题解有判定或代价式记号差异，样本只记录结构，讲授时须对照对应题面重新推导。上海A重赛版允许40次交互询问，换版本需重新核对协议。

杭州K将最晚的k个标记提前，不是把最大时刻直接减k；杭州L的取整代价需要处理平局，不能套未经验证的决策单调性。存在其他正确解法时，教练可以自主选择。

## 本轮采样范围

扩展配置 `nwerc-reference` 取自 [NWERC 2024 官方题面](https://2024.nwerc.eu/main/problem-set.pdf) 与[官方解题](https://2024.nwerc.eu/main/solutions.pdf)，包含A—M十三题。它们支持规则实现、状态设计与多模型组合的扩展讨论，没有跨年份频率统计；不推导中国赛区或西安趋势。

WF 扩展诊断只读了 [2024 World Finals 官方题面](https://icpc.global/worldfinals/problems/2024-ICPC-World-Finals/icpc2024.pdf) 的 B、I、L，能力映射是教学推断。没有核验这些题的完整官方题解。交互程序的刷新与协议要求另依据[官方交互评测说明](https://docs.icpc.global/wp-content/uploads/2024/08/2024-JudgingNotes.pdf)。

[QOJ 西安目录](https://qoj.ac/category/87)用于更多年份原题入口。2025全卷已完成题意与官方题解核验，但现场榜和目标届次奖牌名单尚未完整核验，不生成专题权重或奖牌保证。采用 [NCNA 公布的区域赛规则](https://nc.na.icpc.global/rules/)作通用赛制背景，也不能把它视作西安本届现场规则。

## 小鲸怎样使用

1. 先确认目标、剩余时间和个人/团队训练场景。选择 profile 时解释样本范围，不能从比赛名字推断考纲。
2. 用 VP 可观察事实形成诊断假设。失败原因经代码或复盘确认后，才称为短板；成功记录保留为能力基线。
3. 挑一个能完成验收的动作，说明它对应什么比赛任务、为何现在练、预计投入和改变安排的条件。
4. 讲知识点时先要求识别和证明，接着给边界反例，再找未标注专题的新题与隔天复测。来源跟随卡片一起展示。

用户临时问新知识点时可以回答。回答不自动成为主线任务，也不自动改变游标或阶段。

## 2.5：给教练续课依据，不代替教练判断

本版只增加 `coach_note` 的读写入口，笔记放进现有 `PROGRESS.nodes.<id>.lessonNotes`。
记录是“当前教学判断 + 下一次接续点”；可选学生原话通过 dsh 原生 `sessionQuery`
核对当前会话的真实用户消息，来源由程序生成。插件消息或压缩摘要不能成为学生原话。
核对存在不证明理解，笔记也不改变游标、掌握状态、待办或检测结果。

`coach_status` 和原有会话首步注入只提供短笔记，详细材料按需读取。
默认读取优先接续最近有笔记的未完动作，再看游标；无游标时看最近笔记。
写入默认落在当前游标，指定节点时使用该节点，不改变游标本身。
教学进展或中断值得保存时才写，不要求每轮留笔记，不规定固定工具顺序。
能力排名作为参考，前三之外或尚未映射到能力的节点仍允许教练安排；
课程、前置和写入证据的检查保留。`teachMinutes` 是计划，不自动生成已教学日期，
实际开始学习仍由教练显式记录；旧记录保留，不重新推断发生过什么。

这个取舍是结合本插件所做的设计判断：

* [Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)
  与 [OpenAI：A practical guide to building agents](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/)
  都建议从简单、可验证的方案开始。因此沿用小鲸这个 agent，未增加多教练编排或框架。
* [Anthropic：Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
  支持保留必要摘要、按需获取详情；本版沿用原进度文件与宿主会话查询，不复制聊天数据库。
* [Anthropic：Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)
  强调清楚、职责明确的工具与真实任务评测；本版把续课笔记与已有检测、日程工具分开，
  不用固定调用次序判断教练是否正确。
* [Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)
  区分任务结果与交互质量；工具回归只能验证记录和来源，不能据此声称学生学习效果已证实。

验证覆盖跨模块实例读取、原话来源、拒绝伪引用和并行更新时保留已有进度。
没有做真实学生的长期对照试验，也没有把笔记数量当教学质量分数。

## 四个明确的教学边界

最短路卡提供有向边 `s→a:2`、`s→b:5`、`b→a:-4`：确定后不再更新的 Dijkstra 会过早确定 a；真实最短距离是 1。算法仍偶尔得到对的结果不能证明它适用于负权图。[技术依据](https://oi-wiki.org/graph/shortest-path/)

SCC 卡提供中心与三个叶子组成的双向星形图：四个点互达，但简单路径最多访问三个点。收集每个点必须保持简单路径时，不能把整个分量点权直接相加。[技术依据](https://oi-wiki.org/graph/scc/)

线段树卡对比 `[0,4]` 与 `[2,2]`：两段长度和区间和相同，各项与 2 取最小值后的区间和分别是 2 和 4。只维护和及长度不足以支持此更新，需要补信息或更换算法。[技术依据](https://oi-wiki.org/ds/seg/)

DP 卡要求证明状态足够。同一个位置如果对应不同剩余资源，而后续可选动作依赖资源，就不能直接合并这两段历史；这是状态设计问题，增加模板数量不能解决。[技术依据](https://oi-wiki.org/dp/basic/)

## 验证与范围

`node --test dev/catalog-check.mjs` 检查唯一 ID、真实 MAP 节点、能力映射、每张卡所需字段、公开来源链接、profile 状态与采样限制。该测试不向外网请求，也不读写用户训练账本。

集成回归已验证 profile 可被目标选中且保留限制、`coach_lesson` 的证据闸门，以及两场测量从公开导入到阶段推进的闭环。目录校验不等于小鲸对话效果评测，也没有验证具体练习的完整 AC 程序。
