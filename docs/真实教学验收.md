# 真实教学验收

这是手动开发验收入口。默认显示帮助，普通 `npm test` 和 GitHub CI 不调用模型。`--run` 使用你配置的聊天模型和 Hindsight 服务，可能产生模型费用。

## 1. 配置已安装的 dsh 与模型

需要 Node 支持 `DatabaseSync.setAuthorizer`，本机已验证 Node 24.18；不满足时拒绝运行验收。生产插件仍支持 Node 24。

PowerShell 示例（路径换成你的安装位置）：

```powershell
$env:DSH_EVAL_CLI = 'C:\你的安装目录\dsh\lib\bin.js'
$env:DSH_APP_NODE_MODULES = 'C:\你的安装目录\node_modules'
$env:DEEPSEEK_API_KEY = '你的 DeepSeek 模型 Key'
$env:HINDSIGHT_URL = 'http://127.0.0.1:18888'
npm run eval:teaching -- --help
```

`DSH_APP_NODE_MODULES` 需包含 `@deepseek-ai/dsh-base` 等原生依赖，且与 CLI 来自同一套安装；不能把全局 npm CLI 和 desktop 的 SDK 混用，即使两者版本号相同。省略时会从该 CLI 自动解析依赖目录。CLI 能从本包解析 dsh 时可以省略 `DSH_EVAL_CLI`。默认模型是 `deepseek-flash`，推理配置 `max`，使用官方 Anthropic 兼容接口；可通过 `COACH_EVAL_MODEL`、`COACH_EVAL_REASONING`、`COACH_EVAL_MODEL_URL` 修改，模型需与安装的 dsh 适配器兼容。模型 Key 和可选的 `HINDSIGHT_API_KEY` 只从环境继承，不复制个人凭据文件、个人预设或正式会话。

## 2. 准备公开夹具

```bash
npm run eval:teaching -- --prepare
```

输出一个独立验收目录，默认在系统临时目录；也可用 `--out <父目录>` 指定保存位置。只复制 npm 公开包、随包知识地图与题池，不同步 CF 或 VP，不复制个人数据库。八个场景分别有自己的 `DSH_HOME`、知识目录、SQLite 和随机 `coach-eval-<UUID>` bank。

`decide` 与 `retarget` 的目标和课程夹具由插件自己的存储层写入（不是手写 YAML），所以课程版本、绑定目标和待完成动作都和真实运行同形；`retarget` 会在建课后再改一次目标，制造真实的「课程绑旧目标」状态。所有夹具都标记为人工数据，不能算真实训练历史。

“昨日续课笔记”明确标记为人工夹具、尚未核对，不能算成真实学生表现。准备后修改源码会使副本指纹失效，需要重新准备。验收证据留在独立目录，不随 npm 包发布。

## 3. 串行运行一次

```bash
npm run eval:teaching -- --run <上一步输出的目录>
```

只运行某一场：

```bash
npm run eval:teaching -- --run <目录> --case continuity
```

每场固定两次学生输入，上限三次，不自动重试。场景开始后写一次性锁，避免重复付费；修复启动问题或修改版本后重新准备一个目录，旧失败证据保留。每轮最多等四分钟，未完成、等待审批或出错都不能算通过。原生服务只监听回环地址，不打开浏览器，退出时停止测试进程。

| 场景 | 实际检查 | 人工验收标准 |
|---|---|---|
| `continuity` | 第一轮教学后真正新建另一个原生会话，沿用同一测试账本 | 读懂续课笔记，接上未完成处；核对新原话，不重开无关课程，不虚报掌握 |
| `repair` | 正序更新的错误理解与后续解释 | 用一个物品的反例说明复用本轮状态，再核对不变量；根据初始化疑问调整讲法 |
| `replan` | 时间缩短后，收到口头复测的新表现 | 用新回应缩小收尾目标，区分已解释与仍未会的部分；保留下一课入口，不把口头复测写成独立 AC |
| `contest` | 铜牌队 13 题做出 4 题，后半场提交稀疏；补充当时 B/C 两题进度 | 不从未提交推断未读题，不把高难剩余题算成扫题失败；结合候选题、代码状态和剩余时间评价取舍，证据不足时保留未知 |
| `decide` | 目标与课程有效、押着一个未完成动作；第二轮把剩余时间从 40 分钟缩到 25 分钟 | 只给一个能立即开始的动作；先处理未完成动作或说明改期理由；时间盒、交付物、完成后的检查齐全；缩短后重排且不把未做算成进展 |
| `retarget` | 课程按西安站建立，目标改成香港站后再问今天练什么 | 发现课程与目标不一致并说明；不用旧阶段理由布置；保留旧记录、不自动重写课程；给出复核后的下一步 |
| `integrate` | 在具体题里问离散化，接着追问端点重复与长度信息 | 在题型里讲识别条件与实现边界；不单独开课、不宣布整个大类掌握；用小例子核对理解 |
| `gap` | 没有任何 VP 或提交数据，直接问能不能训练 Top Tree（该节点没有范围卡） | 明确说明证据不足、不编题号或频率；只给一个现在能做的取证动作；说明它不能证明什么 |

## 4. 阅读证据，分别判定

`report.md` 是可读检查表，包含工具调用前后的全部可见教学文字；最后一句收尾不能代替整轮讲解。`report.json` 是机械结果。每场的 `turn-1.json` / `turn-2.json` 保留学生输入、最终答复、原生工具事件、真实 session / seq / time，以及四份训练账本的前后快照；不存在的文件明确记为缺失。`result.json` 保存场次结果，`home/knowledge` 是测试账本，`isolation-audit.log` 是请求审计。证据删除思维链、replayState，并脱敏模型 Key、本地登录 token 和 Cookie。

停止测试进程前，短暂等待桥的归档响应。`memory.accepted` 只表示后端接收请求；`pending` 大于零时归档未确认，不宣称已记住，更不等于后台提炼完成。

机械检查只证明：原生轮次完成、有最终答复、输入没有超过限制、运行副本与准备清单一致。它不证明学生理解，也不会用关键词或另一个 LLM 自动打教学分。每场的判分项写在 `report.md` 里（按场景不同），人工逐场核对。通用四条：

1. 回复中的学习结论是否能对上学生实际原话？
2. 反例与推理是否正确，是否回应了新误解？
3. 时间预算和下一步是否随实际表现调整？
4. 账本是否保留未完成处，有无捏造独立性、耗时或已验证状态？

这轮验证新会话接续与昨日时间夹具，不宣称已真实跨过 24 小时。要检查实际跨日表现，需要隔日保留同一测试账本另做人工接续。本轮禁止终端、委派、工作流和子进程执行，因此不验收代码编译或完整在线判卷。

隔离使用 Node 原生写入／进程权限，加数据库路径与 SQLite authorizer、链接路径检查以及限定端点的网络门禁；它是可信运行时的误用防护，不是对恶意代码的操作系统沙箱。生产小鲸的工具权限不受本验收限制影响。

dsh 的宿主加载器必须加载已安装的原生模块加载扩展，因此验收进程允许 native addons；这会削弱对恶意代码的权限保证。代码只运行可信 dsh 与公开插件，子进程、委派和任意代码执行入口仍被禁用，不把该设置称为安全沙箱。正式 bank 仍受精确请求门禁限制。
